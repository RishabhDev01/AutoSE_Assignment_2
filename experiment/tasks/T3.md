# T3 – Add Gzip-Compressed JSON Storage

## Task Specification

1. TinyDB must provide a storage option that persists database data as gzip-compressed JSON.
2. Data written to this storage must be readable again with its original structure and values.
3. The storage must be publicly importable from both `tinydb.storages` and the top-level `tinydb` package.
4. The storage must work when configured through `TinyDB`.
5. It must also work with `CachingMiddleware`.
6. The compressed file should generally occupy less space than the equivalent uncompressed JSON file for compressible data.
7. File access modes and storage lifecycle behaviour must be handled correctly.
8. Invalid or corrupted compressed data and file-related errors must be handled appropriately.
9. Existing TinyDB serialization behaviour must be preserved.

## Design-Fit Checks

Award one point for each YES answer.

| ID | Design-fit check | Score |
|---|---|---|
| T3-C1 | Does the new storage subclass the existing abstract Storage class? | 0 or 1 |
| T3-C2 | Does it avoid adding a new third-party dependency? | 0 or 1 |
| T3-C3 | Is the implementation placed in storages.py and exported through the existing public API? | 0 or 1 |

Maximum score: 3.
