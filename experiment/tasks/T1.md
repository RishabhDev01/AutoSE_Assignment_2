# T1 – Fix Generator Exhaustion in `one_of()` Queries

## Task Specification

1. The `one_of()` query must work correctly when its candidate values are provided as a generator or an ordinary list.
2. A query using a generator must evaluate correctly across multiple documents.
3. Repeated searches using the same query must return consistent results.
4. Queries created with equivalent generator and list values should behave consistently, including query equality and hashing.
5. Candidate values that are unhashable must continue to be supported.
6. Existing `one_of()` behaviour for ordinary lists must remain unchanged.

## Design-Fit Checks

Award one point for each YES answer.

| ID | Design-fit check | Score |
|---|---|---|
| T1-C1 | Does the solution preserve the existing QueryInstance and Query architecture instead of introducing a separate query system? | 0 or 1 |
| T1-C2 | Does it handle generator inputs without changing the existing behaviour of list, tuple, set and range inputs? | 0 or 1 |
| T1-C3 | Does it preserve query identity and hashing through the existing query and utility mechanisms? | 0 or 1 |

Maximum score: 3.
